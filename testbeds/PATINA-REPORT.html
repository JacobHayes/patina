Verification method (applied at every rung)

  • Native-first baseline: every testbed's run-native.sh passes without patina before patina touches it (done in the previous phase; harnesses are std-pure and swap via a single RUNNER variable).
  • Works under patina: the application behaves as expected and patina itself does not error.
  • Determinism: ≥5 seeds, each run ≥3 times; recorded traces and guest output must be byte-identical across repeats (SHA-256 of trace files).
  • Replay: a recorded trace replays exactly.
  • Bug-finding power (buggy-smoke): patina must produce a deterministic failing run for every one of the six planted bugs — a canary that each patina capability (scheduler, crash injection, latency, network reorder, entropy) can actually find "its" bug.
  • Performance: median wall time of the release-built native binary vs the same binary under patina (compile time excluded, warm-up run discarded), yielding a slowdown ratio and a cost-per-10k-tests estimate.
  • Independent verification: each rung is executed by a dedicated agent, then the coordinator re-runs the key commands before the rung is accepted.

What this rung added to patina

  • native-run --mount <DIR> — the missing piece for real programs: the (uninterposed) supervisor walks a host directory into a sorted, fail-closed filesystem image, streams it into the guest over an inherited fd, and folds the image's SHA-256 into the run fingerprint, so a trace replayed against a different corpus is refused. Guest readdir order is provably independent of host filesystem iteration order (adversarial image decode + host-order-independence tests). Mounted read-only at guest root /, guest cwd = /.
  • isatty interposed to deterministic "not a terminal" — guest output can never depend on host tty state (was the one genuinely-reached flagged symbol).
  • Bug found & fixed in cargo-patina: installing two inherited descriptors (corpus image + trace) clobbered one — only reachable with --mount + record/replay together; fixed via F_DUPFD relocation.
  • The 27 remaining flagged symbols are rg's subprocess-spawn family (fork/posix_spawn*/…, reached only via --pre/-z, never by the battery) — passed as a named allow list with per-symbol justifications, never all, so any new import still fails closed. Flagged follow-up: reachability-aware auditing could clear these properly.

Linux campaign (second platform pass)

All 8 Linux gates green and all four testbeds pass on Linux (Ubuntu 24.04 aarch64 VM, glibc 2.39) — the recent build-out's first run on a second platform, and it caught real bugs macOS could never show. Coordinator verified the gate log and re-ran the six-bug battery on the VM directly (6/6, allowance-free).

  • errno-constant bug (the big one): the shim's Rust-layer errno values were hardcoded macOS numbers — on Linux, EWOULDBLOCK (35) reads as EDEADLK, so every contended-mutex futex retry and every non-blocking UDP read looked like a fatal "Resource deadlock avoided" (raft: zero elections). Now per-target constants, proven by the raft cluster converging.
  • Linux-only guest surface closed: glibc spawn/IPC family deny-trapped (pidfd_*, pipe2, socketpair, …), LFS variants (pread64/pwrite64/fdatasync) interposed, and the rand crate's raw SYS_getrandom syscall routed through seeded entropy.
  • Vacuous-schedule floor recalibrated by measurement: a do-nothing thread costs 4 yields on macOS (dispatch Parker) but 0 on Linux (futex; the join handshake parks the main thread) — the floor is now per-target, which also fixed a latent false-positive on Linux.
  • Host-alias doctrine completed on Linux: -Wl,--wrap=dlsym gives the shim the real glibc resolver while guest dlsym stays neutered; control-plane allowance shrank from 6 symbols to 2 ({dlsym, pthread_create}, the latter wrap-contained so the name can't escape); the static shim-object check now enforces the doctrine on ELF too.
  • Expected deltas, documented: catching seeds and trace hashes differ per platform/binary (determinism across repeats holds on each); newer clippy caught three lints; one OOM flake on the 3.8 GB VM during cold rebuild (benign, warm run clean).

Fuzz campaign — raft-rs, 5000 combined-fault generations

Status: PASSED — zero safety, determinism, crash, or infrastructure defects across 5000 generations (two waves). A randomized-but-deterministic fault-combination campaign on the raft rung (testbeds/raft-harness/fuzz-sweep.sh): where the rung-4 battery exercises each fault axis in isolation, this crosses them — net loss, jitter, sleep jitter, fs-crash, kill/restart, and paced client load, 2–3 at once — sampled deterministically per generation. Zero SAFETY_BUG, zero DETERMINISM_BUG, zero UNEXPECTED_CRASH, zero INFRA_ERROR across all 5000 generations and their determinism-tier double-runs. Every finding is liveness, never safety — and none is a patina or raft defect: gen 46 is genuine raft no-PreVote behaviour, and the 9 wave-1 cases all resolved as a harness workload-shape artifact (a no-dedup client re-proposal) that the dedup fix eliminated — wave 2 (gens 3001–5000, dedup-fixed harness) added zero new findings and zero WORKLOAD_SHAPE.

Method — a deterministic portfolio, not a single axis

Every generation G's entire configuration is a pure function of G (all knob values derived from SHA-256("patina-fuzz-$G")), so any generation is re-runnable by number alone — the property that made incident recovery a one-liner (below). Configs are drawn from a three-tier portfolio, itself selected by G:

  • BREADTH (~80%) — short 20/40-proposal runs combining 2–3 fault knobs; samples many schedules cheaply.
  • TRAFFIC (~15%) — long-horizon 200/400-proposal paced workloads (small propose-window, jitter always on, light-to-moderate loss), ~half with a multi-kill rolling-restart-under-load plan; reaches deep accumulated state — a realistic "steady traffic with rolling restarts" shape rather than a single burst.
  • DETERMINISM (~5%) — a config from either space run twice, required byte-identical (RAFT_RESULT + trace SHA-256) or it is a DETERMINISM_BUG.

Why a portfolio beats a single axis: patina's runtime is deterministic, so one seed is exactly one execution. Sweeping breadth therefore samples the schedule space (each seed a distinct interleaving), while depth reaches the accumulated-state space (long paced runs a short burst never enters). Neither alone suffices — a million short seeds never build a 400-entry replicated log under sustained loss, and one long run explores a single schedule.

The outcome classifier is a pure function with its own selftest (21/21, covering every class — including a planted RAFT_VIOLATION that must read as SAFETY_BUG even on exit 0, and an infrastructure line that must not read as a crash). Three properties keep it non-vacuous and trustworthy: a 10× liveness escalation (a non-heavy liveness timeout is re-run at 10× virtual budget — converges ⇒ it was merely slow, still fails ⇒ a confirmed finding), INFRA_ERROR isolation (environment/build failures are detected, retried once, and never counted as bugs), and a single-instance lock (below).

Finding: gen 46 — no-PreVote election churn (root-caused)

The single finding in the clean 1–1000 window, reproduced identically by two independent runs and by the coordinator. Config: 30% packet loss + paced sparse traffic (propose-window 2, 40 proposals) with a mid-run kill/restart. Symptom: the cluster converges only very slowly — 10/40 at the 180 s virtual budget, 30/40 at 10×=1800 s, full convergence by ~3600 s virtual. Root cause is raft-rs 0.7 defaults: pre_vote=false and check_quorum=false. Under sustained loss a partially-disconnected follower repeatedly times out and force-increments the term, disrupting the sitting leader — the canonical failure mode PreVote exists to prevent. The kill is a red herring: a paced control with no kill shows the same churn — paced terms=46 vs. unpaced terms=1 isolates pacing under loss, not the restart, as the driver. Verdict: genuine raft behavior, not a patina defect, and not a safety issue — the textbook motivation for enabling PreVote. Coordinator-verified.

Findings: 9 extended-range cases — resolved (harness workload-shape artifact)

The 1001–3000 wave surfaced 9 further UNEXPECTED_LIVENESS cases (all liveness, zero safety). Incident & hardening — a concurrent-writer collision, caught loudly

Mid-campaign, a second sweep instance ran against the shared out-fuzz/ and target/ concurrently with the live campaign. Its startup native-build rewrote the harness binary while running guests were exec'ing it, and macOS SIGKILLed every guest in both instances for ~2 minutes (cargo-patina: Cargo process terminated by a signal, instant exit, empty traces); a concurrent rm -rf out-fuzz also truncated the shared log. Crucially the failure was caught loudly, not silently absorbed — the classifier flagged the whole window rather than scoring empty runs as passes. Recovery was trivial because every generation is a pure function of its number: the polluted range was simply re-run by generation number (the 1–427 row above), producing byte-identical configs and clean results with zero contamination in the final numbers. Hardening landed in response:

  • Marker precision: an infrastructure cargo-patina: line is no longer mis-read as a patina runtime crash (the crash marker had been over-broad).
  • INFRA_ERROR retry-once: an environment/build failure is retried once and, if it recurs, recorded as INFRA_ERROR — surfaced and kept, never counted as a raft/patina bug; the run reports "incomplete" rather than a false pass.
  • Single-instance lock: a mkdir-atomic lock under target/ with PID-based stale-lock detection (a dead holder's lock is stolen, so a crash never wedges the tool); a second concurrent sweep now refuses rather than corrupting the shared binary. Proven in the field — the next stray verification run refused instead of colliding.
  • PATINA_FUZZ_OUT override so an intentional isolated verification/triage run uses a private output dir.

Process rule adopted: shared mutable state (out-fuzz/, target/, built binaries) is single-writer while any campaign is live; the lock enforces the sweep-vs-sweep case.

The virtual clock makes even 200/400-proposal TRAFFIC gens cheap; the dominant cost is the 10× escalations, each burning minutes of real time on the churny traffic generations — deliberately, since that is the price of confirming a liveness finding rather than guessing at it.

Patina fixes & patches (cumulative)

Issues found by the campaign, all in patina itself:

  1. macOS Parker escape — LANDED (soundness): std's thread Parker is backed by dispatch_semaphore, not interposed — park/park_timeout (and everything on top: mpsc recv/recv_timeout, contended std locks) escaped the deterministic scheduler and virtual clock silently. Root cause was subtle: the shim's own scheduler baton used the same dispatch_semaphore_* symbols, and the name-based --allow for the baton silently covered std's Parker too. Fix: baton moved to a Mach semaphore (a primitive std never touches); the dispatch surface is now interposed and routed through DetScheduler + VirtualClock (sched_yield too). Bugs found in the programs under test

No real bugs found in ripgrep, redb, or raft-rs — and each clean bill is backed by a non-vacuous oracle (every checker demonstrably fires on planted failures). The nuanced findings:

  • redb 4.1.0: durability held at all 346 injected crash points; the known open-time panic did not reproduce under whole-block torn writes — redb fail-closed with a clean Err in every too-torn case (better behavior than its reputation; a sub-block torn-granularity knob is the noted follow-up for hunting the panic).
  • raft-rs 0.7.0: safety invariants held under reorder, 10–50% loss, and storage crashes; at 50% loss it degrades exactly as the protocol promises (liveness timeouts, never safety violations).
  • ripgrep 15.2.0: 22/22 outputs identical to native under full interposition.

The campaign's bug haul was in patina itself (by design — that was the ladder's purpose): eight substantive issues found and fixed, listed above, each converted into a permanent regression gate. The buggy-smoke canary keeps the bug-finding machinery honest: all six planted bugs are caught, deterministically, forever (its scripts are regression gates now).

Performance summary & cost model

Numbers from this machine (Apple Silicon, macOS), warm, release builds, medians. The headline: a patina test costs ≈3× native wall time on CPU/fs-bound work, and can cost less than native on sleep/fsync-heavy work (virtual clock + in-memory fs skip the real waits).
