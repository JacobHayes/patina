Verification method (applied at every rung)

  • Native-first baseline: every testbed's run-native.sh passes without patina before patina touches it (done in the previous phase; harnesses are std-pure and swap via a single RUNNER variable).
  • Works under patina: the application behaves as expected and patina itself does not error.
  • Determinism: ≥5 seeds, each run ≥3 times; recorded traces and guest output must be byte-identical across repeats (SHA-256 of trace files).
  • Replay: a recorded trace replays exactly.
  • Bug-finding power (buggy-smoke): patina must produce a deterministic failing run for every one of the six planted bugs — a canary that each patina capability (scheduler, crash injection, latency, network reorder, entropy) can actually find "its" bug.
  • Performance: median wall time of the release-built native binary vs the same binary under patina (compile time excluded, warm-up run discarded), yielding a slowdown ratio and a cost-per-10k-tests estimate.
  • Independent verification: each rung is executed by a dedicated agent, then the coordinator re-runs the key commands before the rung is accepted.

Patina is often faster than native on this testbed: it serializes threads, backs the filesystem with memory, and the virtual clock skips real sleeps entirely — sleep-heavy tests cost near-zero under patina, a genuine economic advantage for DST. Yield-points instrumentation costs scale with the amount of instrumented work executed (near-parity on tiny loops, ~59× on 10k-iteration loops) — so race-hunt with small iteration counts (the lost-update race trips at 2 iterations), and reserve instrumented builds for data-race hunting; the plain build catches the other five bug classes and, thanks to the vacuous-schedule detector, tells you when a clean concurrent result means nothing. One subtlety the campaign surfaced: catching seeds are build-specific (instrumentation reshapes the schedule space — deadlock catches at seed 1 on the plain build but seed 0 on the instrumented one), so the harness sweeps for the first catching seed rather than hardcoding. These micro-runs are startup-dominated; the ripgrep rung (CPU- and fs-bound) gives the honest interposition-overhead figure for the cost model.

What this rung added to patina

  • native-run --mount <DIR> — the missing piece for real programs: the (uninterposed) supervisor walks a host directory into a sorted, fail-closed filesystem image, streams it into the guest over an inherited fd, and folds the image's SHA-256 into the run fingerprint, so a trace replayed against a different corpus is refused. Guest readdir order is provably independent of host filesystem iteration order (adversarial image decode + host-order-independence tests). Mounted read-only at guest root /, guest cwd = /.
  • isatty interposed to deterministic "not a terminal" — guest output can never depend on host tty state (was the one genuinely-reached flagged symbol).
  • Bug found & fixed in cargo-patina: installing two inherited descriptors (corpus image + trace) clobbered one — only reachable with --mount + record/replay together; fixed via F_DUPFD relocation.
  • The 27 remaining flagged symbols are rg's subprocess-spawn family (fork/posix_spawn*/…, reached only via --pre/-z, never by the battery) — passed as a named allow list with per-symbol justifications, never all, so any new import still fails closed. Flagged follow-up: reachability-aware auditing could clear these properly.

Thread pool under the deterministic scheduler

The snapshot battery is single-threaded because --sort path forces rg single-threaded (verified: -j1 ≡ -j4 traces). Without --sort, -j4 runs a real 5-task pool under patina — tasks_spawned=5 max_concurrent=5 total_boundaries=1706 vacuous_threads=0 — with output byte-identical across repeats and seeds. Honest caveat: native rg is also stable on this corpus, so this demonstrates patina runs a real work-stealing pool deterministically, not that it rescued a flaky test.

What this rung added to patina

  • Atomic positional I/O (pread/pwrite interposed as new FsReadAt/FsWriteAt trace ops, atomic within one driver call): redb does all I/O positionally, and allow-listing it would have been unsound — guest fds hitting real libc (EBADF) and, worse, writes bypassing CrashFs would have made the whole crash campaign silently vacuous. The atomic-in-one-op design (rather than C-level seek emulation) is why MVCC readers under --yield-points preemption don't see fabricated torn reads. Trace-format safety: variant tags are name-based (serde-tagged), pinned by test against declaration-order renumbering.
  • flock interposed for the single-opener case, with the in-process double-open divergence documented explicitly (per-inode lock table noted as the sound follow-up).
  • After interposition the pre-run gate passes with zero allowances.

MVCC under preemption

--yield-points --threads 4, 5 seeds: redb's no-torn-read MVCC invariant held at every seed with identical final state, ~11.9M scheduling boundaries, no vacuous threads. Even the plain threaded build is non-vacuous (~19K boundaries) since readers do real interposed positional I/O.

Performance — fsync-heavy datapoint

Patina runs the redb workload at 0.16× native (≈6× faster): native pays a real F_FULLFSYNC per Immediate commit; patina's fsync is an in-memory no-op. Deterministic crash injection on a real database costs less than one native run. Traces: ~28 MiB for a 1000-op run, ~346 KiB for a 400-op crash case.

Fixed 50-proposal workload, median of 5: native 2.007 s vs patina 0.010 s — ~200× faster. The virtual clock collapses real tick sleeps and election timeouts. Distributed-systems DST is patina's economic sweet spot: 10k cluster tests ≈ 100 s of wall time (vs ~5.6 h native). Trace ~642 KiB per run.

Linux campaign (second platform pass)

All 8 Linux gates green and all four testbeds pass on Linux (Ubuntu 24.04 aarch64 VM, glibc 2.39) — the recent build-out's first run on a second platform, and it caught real bugs macOS could never show. Coordinator verified the gate log and re-ran the six-bug battery on the VM directly (6/6, allowance-free).

  • errno-constant bug (the big one): the shim's Rust-layer errno values were hardcoded macOS numbers — on Linux, EWOULDBLOCK (35) reads as EDEADLK, so every contended-mutex futex retry and every non-blocking UDP read looked like a fatal "Resource deadlock avoided" (raft: zero elections). Now per-target constants, proven by the raft cluster converging.
  • Linux-only guest surface closed: glibc spawn/IPC family deny-trapped (pidfd_*, pipe2, socketpair, …), LFS variants (pread64/pwrite64/fdatasync) interposed, and the rand crate's raw SYS_getrandom syscall routed through seeded entropy.
  • Vacuous-schedule floor recalibrated by measurement: a do-nothing thread costs 4 yields on macOS (dispatch Parker) but 0 on Linux (futex; the join handshake parks the main thread) — the floor is now per-target, which also fixed a latent false-positive on Linux.
  • Host-alias doctrine completed on Linux: -Wl,--wrap=dlsym gives the shim the real glibc resolver while guest dlsym stays neutered; control-plane allowance shrank from 6 symbols to 2 ({dlsym, pthread_create}, the latter wrap-contained so the name can't escape); the static shim-object check now enforces the doctrine on ELF too.
  • Expected deltas, documented: catching seeds and trace hashes differ per platform/binary (determinism across repeats holds on each); newer clippy caught three lints; one OOM flake on the 3.8 GB VM during cold rebuild (benign, warm run clean).

Patina fixes & patches (cumulative)

Issues found by the campaign, all in patina itself:

  1. macOS Parker escape — LANDED (soundness): std's thread Parker is backed by dispatch_semaphore, not interposed — park/park_timeout (and everything on top: mpsc recv/recv_timeout, contended std locks) escaped the deterministic scheduler and virtual clock silently. Root cause was subtle: the shim's own scheduler baton used the same dispatch_semaphore_* symbols, and the name-based --allow for the baton silently covered std's Parker too. Fix: baton moved to a Mach semaphore (a primitive std never touches); the dispatch surface is now interposed and routed through DetScheduler + VirtualClock (sched_yield too). Proven by the deadlock catch above.
  2. Audit hole → pre-run gate — LANDED & hardened: the default-deny audit had passed the escaping binary. native-run now runs a default-on pre-exec gate over a full escape-class taxonomy (blocking/scheduling, time, entropy, thread lifecycle, process, filesystem/network, shared-memory/IPC, signals/timers, environment, dynamic-loading, direct-syscall), with instruction-level scanning for inlined svc/syscall/cntvct, a per-class detected-and-denied test, an end-to-end planted-escape binary, and a coverage matrix (crates/patina-target/ESCAPE-CLASSES.md) whose residuals section honestly lists what symbol-level auditing cannot see (inlined raw syscalls, commpage/vDSO time, rdrand-class instruction entropy, MAP_SHARED flag invisibility). --allow-unsupported-symbols downgrades to a loud warning recorded in a trace sidecar. False positives fixed: argv accessors known-safe-listed; confstr interposed to a deterministic value — std guests now pass with zero allowances (verified: byte-identical traces, unqualified determinism).
  3. pthread_rwlock_* were ENOSYS stubs — LANDED: real deterministic writer-preferring rwlock in the scheduler (FIFO writers, batch-woken readers, every grant a recorded decision), with can-fail tests plus a proof that contended std RwLock interleavings are byte-identical per seed, vary across seeds, and replay exactly.
  4. SO_RCVTIMEO fail-closed instead of implemented — LANDED: socket read timeouts are now deterministic virtual-clock deadlines (delivery wins ties). Proven by the udp-order catch.
  5. Experiment plane lacked fault knobs — LANDED: native-run gained seed-driven --fs-crash-at open|write|sync|close[:N], --sleep-jitter-nanos MIN..MAX, --net-jitter-nanos MIN..MAX, --net-drop-permille N (default-off; each with must-trip/must-stay-clean tests; replay with mismatched knobs fails closed). Proven by the no-fsync, tight-deadline, and udp-order catches.
  6. ripgrep rung additions — LANDED: native-run --mount (deterministic host-dir→guest-fs imaging, corpus hash bound into replay), isatty interposed, and a cargo-patina fd-clobbering bug (two inherited descriptors) found and fixed with a regression test.
  7. redb rung additions — LANDED: atomic positional I/O (pread/pwrite as FsReadAt/FsWriteAt trace ops — allow-listing would have silently gutted the crash campaign), flock interposed with the double-open divergence documented, name-based trace tags pinned against renumbering.
  8. raft rung additions — LANDED: pthread_atfork interposed (registration no-op; fork surface is denied). Plus a bug the rung found in the yield-points feature — fixed and verified: instrumented TLS destructors running after task completion took a scheduling point on a dead task (fatal invalid_handle). The fix uses a distinct completed-task sentinel so post-completion teardown no-ops while a never-registered foreign thread still fails loudly (proven by a planted test); the raft harness now runs green under --yield-points with byte-identical results across repeats, and the lost-update catch is hash-identical pre/post fix.
  9. Cooperative scheduler couldn't reach atomics-only race windows — LANDED: threads with no interposed boundary ran to completion, silently serializing schedule exploration. Fix, detection first: (a) default-on vacuous-exploration diagnostic — PATINA_SCHEDULE_REPORT per-task boundary counts plus a loud warning when a spawned thread did zero interposed ops of its own, so "N seeds, all clean" can never again mean "nothing was explorable"; (b) cargo patina native-build --yield-points — LLVM SanitizerCoverage basic-block instrumentation (stable -C flags, no nightly) whose hook calls the deterministic scheduler's yield point, making every loop backedge schedulable. Guest source stays std-pure; native builds untouched; instrumented traces carry a +yieldpoints fingerprint so cross-replay against a plain binary fails closed (proven by test). Proven by the lost-update catch at every seed tried.

Bugs found in the programs under test

No real bugs found in ripgrep, redb, or raft-rs — and each clean bill is backed by a non-vacuous oracle (every checker demonstrably fires on planted failures). The nuanced findings:

  • redb 4.1.0: durability held at all 346 injected crash points; the known open-time panic did not reproduce under whole-block torn writes — redb fail-closed with a clean Err in every too-torn case (better behavior than its reputation; a sub-block torn-granularity knob is the noted follow-up for hunting the panic).

The campaign's bug haul was in patina itself (by design — that was the ladder's purpose): eight substantive issues found and fixed, listed above, each converted into a permanent regression gate. The buggy-smoke canary keeps the bug-finding machinery honest: all six planted bugs are caught, deterministically, forever (its scripts are regression gates now).
